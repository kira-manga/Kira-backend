# First/same-process TEST installation registration

This is a **dormant, first/fresh TEST-only source path**, not a production launch,
HTTP mount, restore qualification or used-run recovery mechanism. This delta has
only been inspected statically; it has not been compiled or executed.

## Two distinct owners

`CatalogTestRunActivationV1.projectForRegistration` selects one retained target
before dispatching an original, newly applied first PROJECT. Only after its known
commit, final projected reload and actual SQL/provider/file cleanup can the
original issue `CatalogTestRunFirstProjectionV1`. The handoff is one-use,
same-caller/same-process and target-specific. It proves **original completion
only**, not authority over the target's resources. A public PROJECT receipt,
ACTIVE row, matching digest, historical replay or supplied observation cannot
construct it. An uncertain original outcome or cleanup cannot be rehabilitated
by a later successful request.

The target uses its **own non-operator runtime root**, from the existing
`VersionBoundPersistenceConfiguration.fromAcquired(...).bindLifecycleOwner()` /
`bindVersionBoundPools()` composition. All named-operator permanent ordinary and
deletion seals remain intact. No normal executor is installed on those roots.
Full D is derived from the target's actual retained pools, capacity policy P,
TEST journal J, acquired consumers, shared publication lanes, reader and
activation configuration, not from the handoff's resource graph.

## Target-owned authentication and fresh-effect check

`ComplaintTestNamespaceRegistrationAttemptV1` spends the completion once and
reserves its own coordinator custody. One finite retained-reader budget covers:

1. Its own authenticated coordinator transaction and locked bounded capture.
2. Connection-free genuine SDK schema3 dual-copy verification against its own
   full-D declaration, trust/retention policy and exact completed envelope/copy
   metadata. The first owner's readback is not reused as the target proof.
3. Its own locked recheck, known commit and actual SQL/provider release.

Both transactions use the existing M/read-committed and E fences, then global
control → TEST scope control → catalog lock/history → all22 counters →
run/resources/notices/audits. The exact projected effect must still be untouched:
zero enrollment, original unused reserve, original notices/audits, unchanged
control/history/P and physical fingerprints. The original lease token is only a
staleness comparison; no LIVE leadership lease is acquired or transplanted.
Registration runs read/lock SQL only: no PROJECT, reserve settlement, audit,
lease, gate or control writes. Missing copies, drift, UNKNOWN and unresolved
cleanup cannot issue a binding or retry with the spent completion.

## Actual installation consumer and lifetime

Only the successful released original target attempt constructs
`ComplaintTestNamespaceRegistrationV1`. It retains the target graph and compact
run/activation identity, not the closed projector/provider/phase graph. The
binding pins one exact ordinary ownership/JdbcTemplate pair, preventing another
permit owner on the same pool from being substituted.

`ComplaintInstallationExchangeAdapter` requires the binding at construction and
use. It derives desired D, P, ingress and installation JWT keys from that exact
target, retaining the existing admission, transaction, current-run, reserve and
audit checks. Successful JWT issuance still follows actual transaction release,
with lifetime checks before and after signing. Binding close or original root
shutdown refuses subsequent construction/use; close is not JWT revocation.

**Registration does not reopen either closed gate.** The genuine first/fresh
fixture therefore exercises actual adapter construction and closed-gate
enrollment denial, not successful launch/enrollment. Bearer/me, owner deletion,
restart/recovery, W06, recharge and HTTP enabling remain outside this slice.
Production `UNKNOWN` launch refusal is unchanged. `CONTROLLED_TEST_ONLY` is used
only by the existing fixture; independent deployment/restore identity,
anti-rollback custody, cloud/retention authority and native launch qualification
remain external obligations.

## Source test coverage, not execution evidence

Eight new declarations in `VersionBoundPersistenceConnectedIT` reuse the
existing real TLS, signed activation, SDK and original cleanup fixtures through
`ComplaintTestNamespaceRegistrationCases`. They cover separate target capture /
raw proof / recheck, no-DML and exact resource consumption, close/shutdown,
one-use/cold-replay refusals, raw-copy and used-effect drift, provider signals,
actual native deferred-commit UNKNOWN, acknowledged-commit callback failure and
unresolved original release. No tests were run for this delta.

The old HTTP/me/owner-create tests deliberately seed synthetic TEST rows. Their
old lower adapter recipe is retained as the explicit **test-only**
`SyntheticInstallationExchangeFixture`, without a registration object or
issuer. Their declarations/assertions remain; they are not relabeled as genuine
